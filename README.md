## 项目定位

亿企工场 SMIS 是亿企工场的安全生产管理业务应用，覆盖安全主数据、双重预防、特殊作业、危险废物、设备设施、人员资质与生产安全过程。菜单及操作由租户配置和实际业务权限决定。

本仓只维护 SMIS 页面、业务 API、领域类型与适配代码。认证、租户、权限、菜单、布局、路由、公共组件、Store 和 Supabase 公共客户端由 [`art-supabase-pro`](https://gitee.com/art-si/art-supabase-pro) 统一提供。

## 核心能力

| 领域 | 当前覆盖 |
| --- | --- |
| 安全基础资料 | 检查分类、场所、供应商、岗位风险清单、安全责任、作业指导、假期与请假信息 |
| 双重预防 | 风险辨识与评价、分级管控、风险四色图、检查任务、隐患排查整改、治理跟踪、清单与统计报表 |
| 特殊作业 | 作业工作台、作业类型、危险因素、安全检查项、现场分析，以及动火、受限空间、高处、吊装、临时用电、盲板与断路作业申请 |
| 危险废物 | 危废目录、仓库定义、危废入库与出库记录 |
| 设备设施 | 设备分类、存放位置、设备台账、折旧、报检、特种设备台账与分析 |
| 资质培训 | 课程、题库、考试、培训计划、培训记录、统计报表、工种工项与安全资格证书 |
| 应急救援 | 危险源台账、应急预案、演练计划、演练记录与演练报告 |
| 反违章与文档 | 违章分类、标准库、违章记录、三级教育、公告、安全制度与必知必会 |
| 防护与工器具 | 物资分类、物资信息、个人标准、发放标准、个人申领、领用与归还记录 |
| 事故管理 | 事故快报、工伤申报、事故调查、历史案例与事故统计 |

## 近期完善

- 双重预防工作区补齐风险点、危险因素、评价管控、任务执行、整改通知和治理台账，提供按组织、岗位及任务查看的清单与报表入口。
- 风险四色图提供场景与属性维护；特殊作业复用申请、详情、流程和打印工作区，并提供 AI 预检辅助入口。
- 危险废物目录、仓库和出入库单据形成独立业务域，与普通物资领用区分管理。
- 安全基础、设备、培训、证书、演练和特殊作业表单持续统一为 `ArtForm` 配置，复用组织/人员参选、附件、详情及异步反馈。
- 列表、树形导航、详情和报表补充加载、空态、错误重试与窄屏处理；人员选择沿用平台共享的 HR 读取契约，删除沿用 `MasterDataDeleteGuard` 引用检查。

AI 预检用于辅助核对资料和提示风险，不能代替审批或专业安全结论。AI 只读能力向已启用且具备业务权限的普通用户开放；通过 AI 新增租户主数据仍要求相应 `Add` 权限，其他 AI 业务修改及流程状态变更受平台超级管理员与服务端双重授权约束。

## 安全管理闭环

```text
标准 / 风险 / 资质 / 设备基础
  → 计划与日常执行
  → 检查 / 演练 / 培训 / 领用
  → 违章 / 隐患 / 事故处置
  → 调查、整改、复核与统计分析
```

SMIS 用于形成管理记录和处置闭环，不替代法定检验、专业安全判断或监管要求。关键状态变化、跨租户访问和受控写入必须在服务端校验并留痕。

## 独立运行

环境要求：Node.js `>= 22.13.0`、pnpm `11.28.2`，以 `package.json` 为准。

```powershell
pnpm install
pnpm dev
```

默认访问 `http://localhost:3014`。独立运行时，SMIS 菜单提升为一级入口；由主平台装载时仍保留 SMIS 应用分组。

在主仓工作区中，先按主仓 README 安装依赖、初始化子模块并配置后端。独立克隆时使用已声明的 `art-supabase-pro` 运行时依赖，也可设置 `ART_SUPABASE_PLATFORM_ROOT` 指向主仓。前端环境变量只保存公开客户端配置，服务端密钥不得进入 Vite 产物。

```powershell
pnpm check
pnpm build
pnpm preview
```

`pnpm check` 包含模块边界审计、UI 审计、类型检查、ESLint 和本仓单元测试。生产构建输出到受版本控制的 `docs/`，默认公共路径为 `/art-supabase-smis/`，可作为 Pages 发布目录。

## 租户、权限与删除保护

- 普通用户只能访问本人租户与业务授权范围内的数据；平台超级管理员支持全部租户或指定租户工作区。
- 新增、编辑、审核、发布、领用、归还和流程动作按各自权限校验，租户与权限限制必须在服务端落实。
- 单条与批量删除在确认前检查引用，展示阻止删除的业务记录。检查失败时阻止操作并允许重试，服务端并发拒绝后重新检查。

## 与主仓协作

SMIS 业务修改在本仓提交并推送，数据库变更和跨模块服务契约按主平台约定治理，随后在主仓更新 `modules/art-supabase-smis` 子模块指针。本仓不复制平台公共运行时，也不直接引用其他业务仓前端源码。详细操作见[使用文档](https://art-si.github.io/art-supabase-doc/modules/smis)，回归用例分布在本仓 `tests/unit` 与主仓 `tests/e2e`。
